# Moments AV Runtime Config Hygiene

This public document describes what must stay out of the repository. It does not
list production values, private hosts, provider settings, Store Connect setup,
or release handoff details.

## Source Of Truth

Runtime values are generated by private AVALSYS tooling for maintainers. Do not
add checked-in `.env` files, example secret files, hardcoded production URLs,
signing values, provisioning profiles, or hand-written local config values to
this public repo.

The generated local file is:

```text
apps/ios/Config/Local.xcconfig
```

It is gitignored generated output. Regenerate it whenever switching local,
staging, or release environments.

## Public Rules

- Keep committed xcconfigs free of production runtime values.
- Keep publishable client keys blank unless generated into local ignored config.
- Keep signing team IDs and provisioning values out of git.
- Keep backend URLs, provider configuration, purchase setup, promo codes, and
  reviewer access details in private docs.
- Use private release docs for App Store Connect, RevenueCat, pricing, privacy
  answers, and review notes.

## Validation

After generating local config, maintainers can validate effective build
settings with:

```bash
scripts/check-ios-runtime-config.sh --env staging
```

Use the private release runbook for production archive checks.

The checker should redact sensitive values and fail when local, preview, or
placeholder config leaks into a release build.

## Unsigned Builds

`CODE_SIGNING_ALLOWED=NO` is acceptable for compile checks and isolated tests
only. Authenticated account, purchase, upload, render, and deletion flows need a
normally signed simulator or device build.
